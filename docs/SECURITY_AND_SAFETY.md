# Security & Read-Only Safety Specification (`SECURITY_AND_SAFETY.md`)

## 1. Zero-Trust Read-Only Execution Mandate
This application is strictly a **read-only analytical terminal**. Because the default configuration targets **Port `4001` (IBKR Gateway Live Session)** — or any configured `IBKR_HOST:IBKR_PORT` socket (e.g., `7496`/`7497`) — read-only execution is enforced at the code level through **three independent defense-in-depth layers**.

### Layer 1: Runtime Method Blocking (`ReadOnlyIBGuard` in `src/core/security.py`)
- Feature modules MUST NEVER instantiate `ib_async.IB()` directly.
- Immediately upon instantiating `ib_async.IB()` inside `src/broker/client.py`, `ReadOnlyIBGuard.lock(ib)` overwrites all order-routing and state-mutating methods on both the `IB` instance and its underlying `ib.client` socket object with a trap function that raises `SecurityViolationError`:
  - `placeOrder`
  - `cancelOrder`
  - `reqGlobalCancel`
  - `exerciseOptions`
  - `whatIfOrder`
  - `whatIfOrderAsync`
- `ReadOnlyIBGuard.verify_locked(ib)` returns `True` only if every blocked method on both targets is a trap. Config additionally refuses `ibkr.read_only_enforced: false` (`ConfigurationError`).
- **Mandatory Unit Test (`tests/unit/test_security.py`):** Must invoke every blocked method on a guarded `IB` instance and verify that `SecurityViolationError` is raised with zero network socket writes.

### Layer 2: IBKR Gateway Configuration Checklist
Users running IBKR Gateway on `IBKR_PORT` (default `4001`, or TWS/custom port) should verify in **Configure -> Settings -> API -> Settings**:
1. **Read-Only API:** Checked (`[x]`).
2. **Socket Port:** Matches configured `IBKR_PORT` (default `4001`).
3. **Master API client ID:** Blank (or not conflicting with `CLIENT_ID=77`).

### Layer 3: Static Analysis CI Gate (`Makefile`)
- `make check` runs `make security-guard` (`scripts/security_guard.py`), a static scan of `src/**/*.py` (excluding `src/core/security.py`) that fails on:
  - Order/mutation calls: `.placeOrder(`, `.cancelOrder(`, `.reqGlobalCancel(`, `.exerciseOptions(`, `.whatIfOrder(`, `.whatIfOrderAsync(`.
  - Account/position queries: `.reqAccountSummary*(`, `.reqAccountUpdates*(`, `.reqPositions*(`, `.reqPnL*(`, `.managedAccounts(`, `.reqExecutions*(`, `.reqOpenOrders*(`, `.reqAllOpenOrders*(`.
  - **Strict `SCOPED_ALLOWLIST` in `scripts/security_guard.py`:** permits **only** `.reqExecutionsAsync(` and `.reqPositionsAsync(` inside the single file `src/broker/ledger_sync.py`. Sync variants (`.reqExecutions(`, `.reqPositions(`), all other account/order APIs, and `reqExecutionsAsync`/`reqPositionsAsync` in every other `src/` module remain blocked and fail CI (`tests/unit/test_security_guard.py`).
  - **Runtime Ledger Gating & Mark Cap:** `fetch_gateway_ledger()` in `src/broker/ledger_sync.py` refuses to execute unless `ENABLE_GATEWAY_LEDGER_SYNC=true` (`settings.ledger.gateway_sync_enabled`, default `false`, raising `ConfigurationError` -> HTTP `422 CONFIGURATION_ERROR`); `refresh_open_option_marks()` is capped at `MAX_MARK_CONTRACTS = 60` (`conid`-reused `reqMktData` snapshots with `1 -> 3 -> 4` / `LIVE 1 -> 2` / `DELAYED 3 -> 4` fallback, cancelling every contract in `finally:` even when a pacing sleep raises `CancelledError`).
  - **Exact-Contract Follow-Up, Two-Pass Sequential DTE Budget & Burst Pacing (`src/broker/fetcher.py`):** `fetch_exact_contracts()` shares the same read-only `reqMktData`/`cancelMktData` collector path (`snapshot=False`, zero order/account calls, keeping `scripts/security_guard.py` unchanged), deduplicates active paper-trade legs, skips expired contracts (`expiry < market_day`), and caps requests at `max_contracts_per_page * max_pages_per_refresh` (`400` contracts, `PacingViolationError`). When `include_short_dte=True` (`options_chain.include_short_dte_for_backtest`), `fetch_chain()` runs Pass 1 (`[eff_dte_min, eff_dte_max]`) and completes 100% of its `cancelMktData` teardown before starting Pass 2 (`[short_dte_min, min(short_dte_max, eff_dte_min - 1)]`, keeping each pass `<= 400` contracts and never stacking active subscriptions). Both paged chain pulls and exact-contract pulls pace IBKR bursts via `PAGE_PACING_CHUNK_SIZE = 20` and `PAGE_PACING_PAUSE_SEC = 0.55`, cancelling every subscribed ticker in `finally: await self._cancel_paced(...)` while deferring `BaseException` (including `CancelledError`) until 100% of cancels execute.
  - **Request Time Limits, Qualification Pacing, Stale-`conId` Healing & Disconnect Handling (`src/broker/client.py`, `src/broker/fetcher.py`, `src/services/analyzer.py`):** every staged IBKR request, including the opt-in Gateway ledger sync calls `reqExecutionsAsync` / `reqPositionsAsync` (`src/broker/ledger_sync.py`, previously unbounded), is bounded by `ibkr.request_timeout_sec` (default `25`, `0 < x <= 120`; `GatewayTimeoutError`), and `DISCONNECT_CODES` notices fail pending stages immediately (`RESTORE_CODES` `1101/1102` are log-only). `qualify_contracts()` bounds option/corridor/screener qualification bursts at `QUALIFY_CHUNK_SIZE = 8` per call with `QUALIFY_CHUNK_PAUSE_SEC = 0.45` inter-chunk pacing, link/connection checks, and `_is_usable_contract()` / `_merge_chunk_results()` partial-response filtering. When `PagedOptionChainFetcher` reuses session/CSV-seeded `conId`s (`AnalyzerService._load_known_option_conids` validates tickers with `TickerValidator.validate()` and enforces `_CONID_SEED_MAX_AGE = 7 days` plus positive `conId`/expiry/strike invariants), IBKR Error `200` (`CONTRACT_NOT_FOUND_CODE = 200`) stops before false `3 -> 4` fallback, runs `finally:` `cancelMktData` cleanup, invalidates the symbol's cache/seed, and re-qualifies remaining contracts. On `GatewayTimeoutError`, `run_stage()` calls `reset_after_timeout()` so IB Gateway tears down orphaned `client_id` request queues and auto-reconnects on the next pull (`connection_state` / `connection_notice` pass through `sanitize_client_notice()` in both `IBKRBrokerClient` and `AnalyzerService.get_gateway_status()` so diagnostics surface only scrubbed, single-line status text). Error messages are fixed, sanitized stage/limit text (never raw IBKR text). Timeouts, upstream-loss fast-fails, and cancellation never skip the `finally:` `cancelMktData` cleanup, and no new IBKR API calls are introduced (`scripts/security_guard.py` unchanged).
  - **Single-Flight Concurrency, Corridor Pacing & 100-Line Ceiling Coordination (`src/broker/corridor/`, `src/services/analyzer.py`, `src/services/ledger.py`):** IBKR enforces a 100-simultaneous market-data-line ceiling per session. Wall Strike Corridor subscriptions enforce `DEFAULT_WINDOW_STRIKES = 10` (`1..15`), `DEFAULT_CORRIDOR_MAX_CONTRACTS = 88` option contracts plus `1` spot subscription (`89` total `<= CORRIDOR_MAX_CONTRACTS = 90`), preserving a 10-line safety buffer under IBKR's 100-line ceiling, while `_subscribe_corridor()` paces `reqMktData` bursts at `20` calls per `0.55s` (`PAGE_PACING_CHUNK_SIZE = 20`, `PAGE_PACING_PAUSE_SEC = 0.55`). `AnalyzerService.refresh_lock` (`asyncio.Lock`) serializes all IBKR market-data pulls (`refresh_chain`, `fetch_corridor_quotes`, Gateway-backed `LedgerService.sync_ledger`, and `LedgerService.refresh_open_mtm`), rejecting overlapping calls with `RefreshBusyError` (HTTP `409 REFRESH_BUSY`, `Retry-After: 10`), and explicitly calls `corridor.stop_all_streams()` (cancelling up to 90 streaming corridor lines plus spot and awaiting brief drain) before subscribing new chain, ledger MTM, or paper-trade lines. `open_corridor_stream` also rejects SSE stream opens with `RefreshBusyError` while `refresh_lock` is locked, and the lazily subscribing stream re-checks the lock (`is_busy`) at first subscribe, so a refresh or batch that starts between open and first read ends the stream with `CorridorBusyError` and zero lines opened. `BatchRefreshService` (`src/services/batch_refresh.py`) holds `refresh_lock` for an entire multi-ticker batch (owner `batch:<i>/<n>:<SYM>`), refreshes tickers strictly sequentially (pausing `watchlist.batch_inter_ticker_cooldown_sec` = `2.5` s, `0..30`, interruptible by cancel, between consecutive tickers) so the line budget never exceeds a single-ticker refresh, stops Corridor streams once at start, cancels immediately on request (the running ticker task is cancelled and the fetcher `finally` still runs `cancelMktData`, bounded by `BATCH_CANCEL_CLEANUP_SEC = 10.0` with a warning on expiry and the lock always released; a per-ticker `watchlist.batch_ticker_timeout_sec` cap of `240` s or `GatewayTimeoutError` recycles the socket via `reset_after_timeout()` and — once bounded transient timeout retries (`watchlist.batch_timeout_retries` = `2` across the batch, `0..5`, max `1`/ticker, `watchlist.batch_timeout_retry_cooldown_sec` = `10.0` s, `0..60`, skipped on `consecutive_timeouts >= 2` or underlying-qualification timeouts at `position == 1` / after a prior timeout recycle) are ineligible or exhausted — aborts the batch, as does a `GatewayConnectionError`, and finished pages are archived as partial snapshots without IBKR or paper-quoting calls), and `batch_id` path parameters must match `BATCH_ID_PATTERN` (`^[0-9a-f]{32}$`, else `422`). The screener live leg stream (`src/broker/live_legs.py`, `ScreenerLiveService`) is display-only and bounded by <= 88 option lines AND <= 90 total lines incl. spots (`LiveLegsSpec.validate`, `PacingViolationError` otherwise); Corridor and screener live feeds are mutually exclusive (newer wins), every `refresh_lock` holder stops both (`AnalyzerService._stop_live_feeds`), and the stream re-checks the lock at subscribe time (`ScreenerLiveBusyError`), cancelling every line in `finally:`. The screener run itself makes zero IBKR calls. The screener SSE `q` parameter is capped at 12,000 chars and strictly validated by `_parse_screener_live_query` only (`422 INVALID_REQUEST` with fixed text that never echoes the input, extra fields rejected). Both SSE routes use `_ClosingStreamingResponse`, which always closes the body iterator in a `finally` (live lines released even if the client disconnects mid-send). Application shutdown runs `batch.aclose()` before `stop_corridor_streams()`, then `screener_live.stop_live_streams(reason="shutdown")`, then the broker disconnect; the outer `finally` also calls `screener_live.stop_now(reason="shutdown")` right before the disconnect as a backstop. A Corridor stream that finds the lock held at subscribe time emits SSE `error` `REFRESH_BUSY` (`409`). Watchlist/batch errors map to `409 WATCHLIST_FULL`, `503 STORAGE_UNAVAILABLE`, `404 BATCH_NOT_FOUND` and `409 REFRESH_BUSY`. Per-ticker failures are reported through `describe_error()` as sanitized single-line messages (unknown errors get a generic message, never raw exception text).
  - Event-loop blocking `time.sleep(` and `pandas` imports.
- Diffs touching `src/core/`, `src/broker/`, `src/storage/`, `src/services/`, `src/web/{api,backtest_api,errors}.py`, or `scripts/security_guard.py` are additionally reviewed by the read-only `safety-reviewer` sub-agent (`.agent/agents/safety-reviewer.md`) before commit.

## 2. Ticker Input Validation & Injection Prevention

### 2.1 Dual-Source Ticker Policy
The application supports two ticker selection methods:
1. **Hardcoded Watchlist:** 16 seed tickers (`DEFAULT_WATCHLIST` in `src/core/security.py`, mirrored by `watchlist.hardcoded_tickers` in `config/settings.yaml`): `NVDA`, `AVGO`, `CRDO`, `MRVL`, `META`, `MSFT`, `AMZN`, `TSLA`, `SPCX`, `LITE`, `AMD`, `ORCL`, `PLTR`, `ALAB`, `MU`, `GOOGL`. `WatchlistStore` (`src/storage/watchlist_store.py`) re-validates every entry on read and on every write through `TickerValidator.validate_selection()` (so the `allow_custom_ticker=false` membership guard applies); the read is bounded (`MAX_WATCHLIST_FILE_BYTES` = 64 KiB) and deeply nested JSON (`RecursionError`) is caught, so a file with an invalid, over-cap, oversize, or too-deep payload is treated as corrupt (seed list served, backed up to `watchlist.corrupt.json` on the next change). An unreadable file (`OSError`, or a directory at the path) serves the seed list but refuses all writes (`StorageUnavailableError`), so a transient lock can never overwrite the user's list. Removing a ticker never touches `data/snapshots/` or `data/latest/`.
2. **Dynamic Custom Stock Input Box:** Allows typing any US Stock/ETF symbol in the UI.

### 2.2 Strict Sanitization Pipeline (`TickerValidator` in `src/core/security.py`)
Every ticker input from any source (UI form, URL parameter, query string, JSON payload, or config) MUST pass through `TickerValidator.validate(raw_input: str) -> str` (a classmethod) before being used in file paths or IBKR calls — including `PaperTradeStore`, `PaperTradeService`, `backtest_store`, and `/api/backtest/*` endpoints (where `trade_id` is additionally constrained by `PAPER_TRADE_ID_RE` and snapshot IDs by `SNAPSHOT_ID_RE`). When `watchlist.allow_custom_ticker` is `false`, use the instance method `TickerValidator(watchlist, allow_custom).validate_selection(raw)`, which additionally enforces watchlist membership.
1. **Normalization:** Confirm input is a `str`, strip whitespace, require pure ASCII (rejects Unicode look-alikes such as full-width letters), convert to uppercase.
2. **Strict Regex Gate:** Must match `^[A-Z]{1,5}$` (1 to 5 uppercase ASCII letters only).
   - Rejects path traversal (`..`, `/`, `\`), shell metacharacters (`;`, `|`, `$`, `&`), whitespace, numbers, and punctuation with `InvalidTickerError` (HTTP `422`).
3. **Storage Path Boundary Guard (`Settings._check_tracked_dir` in `src/core/config.py`):** `PaperTrackerSettings.tracked_dir` (default `data/tracked`) is resolved via `resolve_project_path()` and strictly validated to remain inside `storage.data_dir` and never equal to or inside `storage.snapshots_dir`, raising `ConfigurationError` on violation so tracked leg quotes can neither escape the project data tree nor pollute full-chain snapshot discovery.
4. **IBKR Qualification Gate:** Before creating any directory under `data/snapshots/{TICKER}/` or querying option parameters, the broker client must qualify the contract as a US Stock:

    Contract(secType="STK", symbol=validated_symbol, exchange="SMART", currency="USD")

   If `qualifyContractsAsync` returns empty or fails, execution aborts with `InvalidTickerError` and nothing is written to disk.

## 3. Cross-Platform Docker & Localhost Port Safety (Windows & macOS)

### 3.1 Localhost-Only Web Binding
- Native execution (`make run`) binds Uvicorn strictly to `127.0.0.1:8000`.
- Docker execution (`docker-compose.yml`) binds host port mapping strictly to `127.0.0.1:8000:8000` so the web UI is never exposed to external network interfaces.

### 3.1.1 Container Hardening (`Dockerfile`, `.dockerignore`)
- Multi-stage build: dependencies resolved only from `uv.lock` (`uv sync --locked --no-dev --no-install-project`); no dev/test tooling, compilers, or `curl` in the runtime image.
- Runs as the unprivileged `app` user (UID/GID `10001`); only `/app/data` (bind-mounted `./data`) is writable, and `./config` is mounted read-only.
- `.dockerignore` is an allow-list (`pyproject.toml`, `uv.lock`, `config/`, `src/`), so `.env`, `data/`, `.git`, and local virtualenvs never enter the build context or image layers.
- `HEALTHCHECK` polls `GET /api/status` via the Python standard library (works while the Gateway is offline).

### 3.2 Docker-to-Host IBKR Gateway Networking (`Port 4001`)
When running inside Docker on Windows or macOS (`make docker-up`):
- The container connects to IBKR Gateway on the host machine via `IBKR_HOST=host.docker.internal` and `IBKR_PORT=4001`.
- Because traffic from `host.docker.internal` arrives at IBKR Gateway from the local Docker bridge subnet (e.g., `172.17.0.1` or `192.168.65.1` / `192.168.65.254`) rather than `127.0.0.1`, users running via Docker must either:
  1. Uncheck *"Allow connections from localhost only"* in IBKR Gateway API Settings and add `127.0.0.1` plus the local Docker bridge IP to **Trusted IP Addresses** (while keeping **Read-Only API** checked), OR
  2. Run the app natively on the host via `make run`, which connects directly over `127.0.0.1:4001`.

## 4. Credential & Account Privacy Isolation
- **No Credentials Stored on Disk or in Responses:** The application never requests, stores, or logs IBKR usernames, passwords, or 2FA codes. `IBKR_FLEX_TOKEN` (`LedgerSettings.flex_token`, `Field(repr=False)`) is supplied exclusively via `.env` / environment variables (never `config/settings.yaml`, `data/ledger/sync_state.json`, or `/api/status` payloads) and is redacted along with URL `t=...` query strings by `redact_flex_secrets()` (`src/broker/flex.py`) before any `FlexServiceError` (`502 FLEX_SERVICE_ERROR`), `StorageSchemaError` (`422 STORAGE_SCHEMA_ERROR`), or `ConfigurationError` (`422 CONFIGURATION_ERROR`) detail is logged or returned.
- **Scoped Account-Free Ledger Sync & Redaction:** Core option-chain workflows never call `reqAccountSummary`, `reqPositions`, `reqPnL`, `managedAccounts`, or `reqOpenOrders`, and `ib.client.connectAsync` always bypasses `IB.connectAsync` account/order hydration. The opt-in ledger path (`ENABLE_GATEWAY_LEDGER_SYNC=true` in `src/broker/ledger_sync.py`) drops every `account` attribute immediately, and `parse_flex_xml`, `parse_activity_csv`, and `redact_flex_secrets` strip/redact XML tags and both quoted and unquoted IBKR account patterns (`acctId`, `accountId`, `acctCode`, `account`, `ClientAccountID`) before persistence or error surfacing (`data/ledger/` is excluded from git via `.gitignore`).
- **Client Notice & Error Sanitization (`sanitize_client_notice` in `src/broker/flex.py`):** Broker disconnect/timeout notices (`IBKRBrokerClient._on_error`, `reset_after_timeout`, `connection_notice`), `GatewayStatusResponse.connection_notice` (`AnalyzerService.get_gateway_status()`), and `SafeError` payloads (`describe_error()` in `src/services/error_messages.py`) pass through `sanitize_client_notice()` (`MAX_SAFE_MESSAGE_CHARS = 300`), which strips Python tracebacks (`[REDACTED_TRACEBACK]`), applies `redact_flex_secrets()`, redacts quoted/unquoted `token`/`api_key`/`secret`/`password`/`authorization` values and bare `DU`/`DF`/`U` IBKR account IDs, strips control characters, and caps output to a single 300-character line.
- **Safe Manual File Uploads:** `POST /api/ledger/import` performs a bounded read (`await file.read(MAX_LEDGER_IMPORT_BYTES + 1)` with `finally: await file.close()`, where `MAX_LEDGER_IMPORT_BYTES = 20 * 1024 * 1024`), strips POSIX `/` and Windows `\` path separators and requires `.xml` / `.csv` (`InvalidRequestError` `422`), rejects NUL bytes and `(ValueError, csv.Error)` / malformed payloads (`StorageSchemaError` `422 STORAGE_SCHEMA_ERROR`), and validates every underlying symbol via `normalize_underlying` (`TickerValidator`).
